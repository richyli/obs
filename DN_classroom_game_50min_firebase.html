DN classroom game 50min firebase

學生在 50 分鐘內，用 vibe coding 做出一個有 Firebase 後端的新聞遊戲原型——玩家的選擇即時寫入、任何人打開同一頁面都能看到聚合結果。

這是 digital narrative database teaching Pattern E「Compare with Crowd」的課堂實作版，直接對標 DN Climate Game FT 與 DN You Draw It NYT 的核心機制。

四個學習目標

這堂課圍繞四個具體的學習點設計，每個點都有對應的操作時刻：

# 學習目標 在活動中的對應時刻
1 理解「寫入」的概念——資料從使用者進入資料庫 學生按「提交」，自己看到 Firestore Console 多了一筆文件
2 能夠使用 Firebase 完成一次寫入與讀取 填入 config、部署、測試全流程
3 驗證——確認資料確實進去、確實讀得出來 Firestore Console 直接看資料；儀表板圖表反映提交結果
4 建立心理模型——遇到類似情境知道可以用寫入讀取解決 課尾反思：「哪些新聞題目適合這個做法？」

為什麼這個專題需要資料庫

純前端版本 加上 Firebase 後
每個人玩完就消失 每個人的選擇永久留下
看不到別人怎麼選 看到班級、全體讀者的分布
沒有歷史 可比較不同時期的讀者
是個遊戲 是個新聞工具

「你的選擇 + 別人的選擇 = 一個新聞故事」——這是 Pattern E 的本質，也是這個專題比一般靜態頁值得做的理由。

新聞情境示範：核四重啟決策遊戲

（老師課前做好示範版，學生看完再做自己的主題）

設定：你有 100 點，分配給五個能源政策。每種分配產生不同的碳排 / 電費 / 穩定度結果。提交後看到：你的政策輪廓、班級平均、和政府現行政策的差距。

為何好用作示範： - 5 分鐘就能理解規則 - trade-off 明顯：想要低碳就要付錢，想便宜就要犧牲環境 - 聚合圖自然產生一個可報導的故事（「學生比政府更傾向再生能源」）

學生的製作流程（30 分鐘內）

Step 1：決定新聞情境（5 分鐘）

回答三個問題： 1. 你的議題是什麼？（一個台灣真實的政策爭議） 2. 你的讀者要分配什麼？（金錢、點數、空間、時間……） 3. 有什麼 trade-off？（每個選項得到 A 就要犧牲 B）

Step 2：讓 AI 生成基礎程式（15 分鐘）

把老師提供的基礎模板（見下方）貼給 Claude Code / Cursor，加上這段 prompt：

請修改這個遊戲，主題改成「[你的主題]」。
有 [N] 道題目：
- 題目 1：[名稱]，max [X] 點，trade-off 說明：[得到什麼犧牲什麼]
- 題目 2：...
- 題目 3：...
計算結果的邏輯：[描述你想怎麼算出最終分數或標籤]

Claude 會改掉題目文字、slider 範圍、換算公式，其餘 Firebase 邏輯不動。

Step 3：填入 Firebase config、測試（10 分鐘）

  • 老師統一提供一個課堂用 Firebase 專案的 config（貼在黑板或共用文件）
  • 學生把 config 填入兩個 HTML 檔
  • 打開遊戲頁，提交一次，確認 Firestore 有收到資料
  • 打開儀表板頁，確認圖表出現

function calcLabel(choices) {
  if (choices.a >= 25) return "類型 1";
  if (choices.b >= 25) return "類型 2";
  return "均衡型";
}
// 計算三個分數指標（0–100），學生依主題修改
function calcScores(choices) {
  return {
    score1: Math.min(100, choices.a * 2),
    score2: Math.min(100, choices.b * 2 + choices.c),
    score3: Math.min(100, 100 - choices.a - choices.b),
  };
}

import { initializeApp } from "https://www.gstatic.com/firebasejs/10.12.0/firebase-app.js";

const app = initializeApp(FIREBASE_CONFIG);
const db  = getFirestore(app);
const auth = getAuth(app);

const TOTAL = 100;
const ANIMALS = ["水獺","水豚","貓熊","河豚","企鵝","無尾熊","蜜獾","土撥鼠"];
const COLORS  = ["藍","紅","綠","橘","紫","黃","粉","灰"];

document.querySelector("#dashLink").textContent += sid;

let uid;
signInAnonymously(auth).then(r => uid = r.user.uid);

function getChoices() {
  const c = {};
  document.querySelectorAll(".slider").forEach(el => {
    c[el.dataset.key] = +el.value;
  });
  return c;
}

function syncUI() {
  const choices = getChoices();
  document.querySelectorAll(".slider").forEach(el => {
    el.nextElementSibling.textContent = el.value + " 點";
  });
  const used = Object.values(choices).reduce((s,v) => s+v, 0);
  document.getElementById("left").textContent = TOTAL - used;
  document.getElementById("btn").disabled = used > TOTAL;
  document.getElementById("left").style.color = used > TOTAL ? "#e63" : "#2563eb";
}
document.querySelectorAll(".slider").forEach(el => el.addEventListener("input", syncUI));

window.submit = async () => {
  const choices = getChoices();
  if (Object.values(choices).reduce((s,v)=>s+v,0) > TOTAL) return;
  document.getElementById("btn").disabled = true;

  const label  = calcLabel(choices);
  const scores = calcScores(choices);

  await setDoc(doc(db, `sessions/${sid}/players/${uid}`), {
    nickname, choices, label, scores,
    submitted_at: serverTimestamp(),
  });

  document.getElementById("label").textContent = label;
  document.getElementById("scores").textContent =
    SCORE_LABELS.map((l,i) => `${l} ${Object.values(scores)[i]}`).join("　");
  document.getElementById("result").style.display = "block";
  document.querySelectorAll(".q, #budget-display, #btn").forEach(e => e.style.display="none");
};

<script type="module">

let bar, pie;

function initCharts() {
  bar = new Chart(document.getElementById("barChart"), {
    type: "bar",
    data: {
      labels: OPTION_LABELS,
      datasets: [{ label: "本班平均", data: OPTION_KEYS.map(()=>0),
                   backgroundColor: "#2563eb" }]
    },
    options: { scales: { y: { min: 0, max: 50 } }, plugins: { legend: { display: false } } }

      ["#f59e0b","#10b981","#6366f1","#e63","#06b6d4"] }] }

function update(docs) {
  const n = docs.length;
  document.getElementById("count").textContent = n;
  if (!n) return;

  // 平均
  const avgs = OPTION_KEYS.map(k =>
    Math.round(docs.reduce((s,d) => s + (d.choices?.[k] || 0), 0) / n)
  );
  bar.data.datasets[0].data = avgs;
  bar.update();

  // 輪廓分布
  const tally = {};
  docs.forEach(d => { tally[d.label] = (tally[d.label] || 0) + 1; });
  pie.data.labels = Object.keys(tally);
  pie.data.datasets[0].data = Object.values(tally);
  pie.update();

  // 名單
  document.getElementById("tbody").innerHTML = docs
    .sort((a,b) => (b.submitted_at?.seconds||0) - (a.submitted_at?.seconds||0))
    .map(d => `<tr><td>${d.nickname || "—"}${d.label || "—"}</td></tr>`)
    .join("");
}

Firestore Security Rules

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /sessions/{sid}/players/{pid} {
      allow create: if request.auth != null && request.auth.uid == pid;
      allow read:   if true;
      allow update, delete: if false;
    }
  }
}

35-42 分鐘：驗證階段（學習目標 3）

這段是整堂課最重要的教學時刻。 在 Firebase Console 親眼看到自己的資料，是「寫入」概念從抽象變具體的關鍵。

學生檢查清單

驗證寫入： 1. 打開 Firebase Console → Firestore Database 2. 找到 sessions → {今日sessionId} → players 3. 確認看到自己的文件（以 uid 為名） 4. 展開文件，核對 choices 裡的數字和你剛剛填的一樣

驗證讀取： 1. 打開 dashboard.html?s={sessionId} 2. 確認圖表出現、人數 = 已提交人數 3. 請鄰座同學也提交一次，看儀表板數字有沒有即時更新

驗證失敗的常見原因：

症狀 最可能原因
提交後 Console 沒有新文件 config 貼錯或 Anonymous Auth 沒啟用
儀表板圖表空白 sessionId 不一致（game.html 和 dashboard.html 的 ?s= 參數不同）
圖表出現但資料不更新 Security Rules 沒部署（Firestore 預設 30 天測試模式，之後全鎖）

反思討論（建立心理模型）

老師引導的三個問題：

問題 1（關於寫入讀取）
「今天你學到的這個機制——使用者的動作寫入資料庫、任何人都能讀聚合結果——你還能想到哪些新聞題目可以用這個做法？」

→ 目的：讓學生自己舉例，確認心理模型有沒有遷移

問題 2（關於新聞意義）
「如果你把今天做的遊戲放到媒體網站上，讀者的聚合資料能成為一個新聞故事嗎？你會怎麼寫這篇報導？」

→ 目的：連結到數位敘事的新聞本質，而不只是技術練習

問題 3（關於限制）
「你的遊戲資料有什麼樣本偏差？哪些人不會來玩這個遊戲？」

→ 目的：建立資料倫理意識

評量重點（對應 digital narrative database teaching 評分指標）

學習目標 評量問題
目標 1：理解寫入 學生能否說明「按下提交，發生了什麼事」？
目標 2：使用 Firebase 遊戲能跑、資料進 Firestore、儀表板即時更新
目標 3：驗證 學生有沒有打開 Console 親眼確認？有沒有做交叉測試？
目標 4：心理模型 反思討論時，學生舉的新情境例子合理嗎？
