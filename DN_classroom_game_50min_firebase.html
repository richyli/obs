DN classroom game 50min firebase

學生在 50 分鐘內，用 vibe coding 做出一個有 Firebase 後端的新聞遊戲原型——玩家的選擇即時寫入、任何人打開同一頁面都能看到聚合結果。

這是 digital narrative database teaching Pattern E「Compare with Crowd」的課堂實作版，直接對標 DN Climate Game FT 與 DN You Draw It NYT 的核心機制。

老師示範版（可直接使用） - 遊戲頁：[https://richyli.github.io/obs/dn_game.html](https://richyli.github.io/obs/dn_game.html) - 儀表板：[https://richyli.github.io/obs/dn_dashboard.html](https://richyli.github.io/obs/dn_dashboard.html) - 使用方式：遊戲頁輸入課堂代碼 → 學生決策 → 送出後立即看到自己與班級平均的比較；儀表板輸入同一代碼 → 老師投影

四個學習目標

這堂課圍繞四個具體的學習點設計，每個點都有對應的操作時刻：

# 學習目標 在活動中的對應時刻
1 理解「寫入」的概念——資料從使用者進入資料庫 學生按「提交」，自己看到 Firestore Console 多了一筆文件
2 能夠使用 Firebase 完成一次寫入與讀取 填入 config、部署、測試全流程
3 驗證——確認資料確實進去、確實讀得出來 Firestore Console 直接看資料；儀表板圖表反映提交結果
4 建立心理模型——遇到類似情境知道可以用寫入讀取解決 課尾反思：「哪些新聞題目適合這個做法？」

為什麼這個專題需要資料庫

純前端版本 加上 Firebase 後
每個人玩完就消失 每個人的選擇永久留下
看不到別人怎麼選 看到班級、全體讀者的分布
沒有歷史 可比較不同時期的讀者
是個遊戲 是個新聞工具

「你的選擇 + 別人的選擇 = 一個新聞故事」——這是 Pattern E 的本質，也是這個專題比一般靜態頁值得做的理由。

新聞情境示範：核四重啟決策遊戲

（老師課前做好示範版，學生看完再做自己的主題）

設定：你有 100 點，分配給三個能源政策。每種分配產生不同的碳排 / 電費 / 穩定度結果。提交後看到：你的政策輪廓、三個分數指標，以及你的選擇 vs 目前班級平均的即時比較圖（每 5 秒自動更新）。

為何好用作示範： - 5 分鐘就能理解規則 - trade-off 明顯：想要低碳就要付錢，想便宜就要犧牲環境 - 聚合圖自然產生一個可報導的故事（「學生比政府更傾向再生能源」）

學生的製作流程（30 分鐘內）

Step 1：決定新聞情境（5 分鐘）

回答三個問題： 1. 你的議題是什麼？（一個台灣真實的政策爭議） 2. 你的讀者要分配什麼？（金錢、點數、空間、時間……） 3. 有什麼 trade-off？（每個選項得到 A 就要犧牲 B）

Step 2：讓 AI 生成基礎程式（15 分鐘）

把老師提供的基礎模板（見下方）貼給 Claude Code / Cursor，加上這段 prompt：

請修改這個遊戲，主題改成「[你的主題]」。
有 [N] 道題目：
- 題目 1：[名稱]，max [X] 點，trade-off 說明：[得到什麼犧牲什麼]
- 題目 2：...
- 題目 3：...
計算結果的邏輯：[描述你想怎麼算出最終分數或標籤]

Claude 會改掉題目文字、slider 範圍、換算公式，其餘 Firebase 邏輯不動。

Step 3：填入 Firebase 網址、測試（10 分鐘）

  • 老師統一提供課堂用 Firebase Realtime Database 的專案網址（格式：[https://xxx-default-rtdb.firebaseio.com），貼在黑板或共用文件](https://xxx-default-rtdb.firebaseio.com`），貼在黑板或共用文件)
  • 學生把網址填入兩個 HTML 檔的 DB 常數
  • 打開遊戲頁，輸入課堂代碼 → 提交一次
  • 確認出現「你 vs 班級平均」比較圖（代表寫入成功、讀取成功）
  • 打開儀表板頁，確認人數和圖表更新

Firebase Realtime Database 規則

課堂用途只需確保 /classroom/ 路徑可讀寫（Firebase Console → Realtime Database → 規則）：

{
  "rules": {
    "classroom": {
      ".read": true,
      ".write": true
    }
  }
}

老師課前準備

  1. 建一個 Firebase 專案（Console → 新增專案，2 分鐘）
  2. 啟用 Realtime Database（選測試模式即可，或貼上上方規則）
  3. 複製 Database URL（格式：[https://xxx-default-rtdb.firebaseio.com）](https://xxx-default-rtdb.firebaseio.com`）)
  4. 把兩個 HTML 放上任何靜態主機（GitHub Pages / Vercel / Firebase Hosting）
  5. 當天上課前：決定課堂代碼（例如 20260508），公告給學生
  6. 把 Database URL 和課堂代碼貼在共用文件，學生 copy → 貼入 DB 常數

或直接使用示範版（不需自建 Firebase）：把遊戲頁 URL [https://richyli.github.io/obs/dn_game.html?s=課堂代碼](https://richyli.github.io/obs/dn_game.html?s=課堂代碼) 傳給學生，儀表板[https://richyli.github.io/obs/dn_dashboard.html?s=課堂代碼](https://richyli.github.io/obs/dn_dashboard.html?s=課堂代碼) 老師投影即可。

35-42 分鐘：驗證階段（學習目標 3）

這段是整堂課最重要的教學時刻。 在 Firebase Console 親眼看到自己的資料，是「寫入」概念從抽象變具體的關鍵。

學生檢查清單

驗證寫入： 1. 打開 Firebase Console → Realtime Database 2. 找到 classroom → dn_game → {課堂代碼} → 展開 3. 確認看到自己的記錄（以隨機 pid 為 key） 4. 核對欄位 a, b, c 的數字和你剛剛拉的 slider 一樣

驗證讀取（最直接的方式）： 1. 送出後，遊戲頁直接出現「你 vs 班級平均」的比較圖 → 代表讀取成功 2. 打開 dashboard.html?s={課堂代碼}，確認圖表出現、人數正確 3. 請鄰座同學也提交一次，看比較圖和儀表板數字有沒有在 5 秒內更新

驗證失敗的常見原因：

症狀 最可能原因
提交後顯示「送出失敗」 DB 網址貼錯，或 Realtime Database 規則不允許 /classroom/
比較圖沒出現 課堂代碼不一致（遊戲和儀表板的 ?s= 要一樣）
儀表板圖表空白 同上，或 DB 還沒有任何資料

42-50 分鐘：交叉測試 + 反思（學習目標 4）

交叉測試

  1. 各組把遊戲 URL 傳給鄰組（加上 ?s=當日sessionId）
  2. 互玩 2 分鐘
  3. 讓每個遊戲的儀表板至少累積 5 筆資料
  4. 每組 1 分鐘報告：「你的遊戲，最讓人意外的聚合結果是什麼？」

反思討論（建立心理模型）

老師引導的三個問題：

問題 1（關於寫入讀取）
「今天你學到的這個機制——使用者的動作寫入資料庫、任何人都能讀聚合結果——你還能想到哪些新聞題目可以用這個做法？」

→ 目的：讓學生自己舉例，確認心理模型有沒有遷移

問題 2（關於新聞意義）
「如果你把今天做的遊戲放到媒體網站上，讀者的聚合資料能成為一個新聞故事嗎？你會怎麼寫這篇報導？」

→ 目的：連結到數位敘事的新聞本質，而不只是技術練習

問題 3（關於限制）
「你的遊戲資料有什麼樣本偏差？哪些人不會來玩這個遊戲？」

→ 目的：建立資料倫理意識

評量重點（對應 digital narrative database teaching 評分指標）

學習目標 評量問題
目標 1：理解寫入 學生能否說明「按下提交，發生了什麼事」？
目標 2：使用 Firebase 遊戲能跑、資料進 Firestore、儀表板即時更新
目標 3：驗證 學生有沒有打開 Console 親眼確認？有沒有做交叉測試？
目標 4：心理模型 反思討論時，學生舉的新情境例子合理嗎？
新聞 trade-off 設計 題目讓人真的感受到兩難？聚合資料會產生什麼新聞故事？
