Chapter 1 — 入門篇

Claude Code 是什麼？怎麼裝？第一次能拿來做什麼？

  • Claude Code（核心概念與工具導覽）— 必讀。包含 Claude.md、WAT Framework（Workflow / Agent / Tools）、Plug-in 介紹、Skill 系統、Slash Commands、四種自動化模式（Plan / Bypass / Ask / Auto）
  • Claude Code Skills（Skill 機制概覽）— 為什麼 Skill 是 Claude Code 最重要的擴充點
  • Claude code in Action - Coursera（Coursera 官方課程筆記）— 想要結構化學習的人從這裡開始

Chapter 2 — 工作流與方法論

同樣是用 Claude Code，會用的人跟不會用的人差在哪？這一章講核心思維。

  • Claude Code case 03（計劃優先 Plan-First 原則）— 三階段：研究 → 編碼 → 執行；為什麼跳過「計劃」階段會浪費時間
  • Claude code note 20260307-1（Agent Skill 位置分類）— Skill 放在 user / project / plugin 三個層級的差異
  • Claude code note 2603081（Skill 位置 vs. 使用範圍對應表）— 上一篇的查表版
  • claude cowork（Cowork 預覽與不確定性處理）— 當 Claude 不確定時，怎麼讓它停下來問人
  • Claude workflow（36 小時打造個人數位助理）— 一個非工程師的完整方法論
  • Claude Code Conjoint Skill（學術資料分析的 Skill 設計）— 把研究流程做成可重複呼叫的 Skill

我從這些筆記提煉出的 5 個鐵律

  1. 動工前先問技術棧：不要讓 Agent 猜，用多選題快速對齊
  2. 環境檢查放最前面：缺工具就停下來，不要硬幹
  3. 不可逆動作要先告知：裝套件、改設定、刪檔、推送 → 先問
  4. 善用官方模板：dotnet new、npm create、cargo new
  5. 以「能跑」為完成條件：build 通過、tests 通過、瀏覽器看到畫面才算完

Chapter 4 — 進階應用與延伸

已經會用 Claude Code 了，怎麼進一步優化？

  • Claude Codex（Claude Code + Codex CLI 生圖）— 串接其他 CLI 工具的範例
  • Claude code case 1（快速技巧集合）— 快捷鍵、Bash 叫用、重新執行

  • Claude Code N 260304（外部資源連結）

自動化進階：Yes-All 模式

claude --yes --skip-confirm

或在專案根目錄放 .claude.json：

{ "autoYes": true, "skipConfirm": true, "silent": false }

⚠️ 記得加進 .gitignore，不要強迫隊友共用自動 yes。

我給讀者的三條閱讀路徑

  1. Claude workflow 看非工程師如何系統化
  2. Claude Code Conjoint Skill 看研究流程 Skill 化
  3. Claude Codex 看跨工具串接
