案例：用 Claude Code 從零做出一個 Windows 桌面猜拳程式

日期：2026-05-14 技術棧：C# WinForms + .NET 8 完成時間：約 15 分鐘（含 SDK 安裝） 最終產物：projects/RockPaperScissors/（含可執行 .exe）

為什麼選這個案例當教材

這個案例的價值在於它涵蓋了一個從零開始的小程式專案會遇到的所有典型障礙，而且每一個障礙的處理方式都可以複製到別的專案：

  1. 技術棧選擇：使用者只說「Windows 桌面、亂數猜拳」，沒有指定語言
  2. 環境不完整：開始寫之前才發現只有 .NET Runtime 沒有 SDK，無法編譯
  3. 資源依賴：要做「圖片動畫」但又不想處理 PNG/ICO 檔案路徑問題
  4. 驗證閉環：寫完不能只丟程式碼，必須真的 build 過、產出 .exe

完整對話流程

Step 1 — 確認技術棧（用 AskUserQuestion，不要猜）

第一個訊息「我想寫一個 windows desktop 的程式，亂數猜拳」之後，Claude 沒有直接動工，而是用 AskUserQuestion 問了兩件事：

  • 技術棧：Python tkinter / Python PyQt / C# WinForms / Electron
  • 功能範圍：三選一基本款 / 計分板 / 圖片動畫 / 難度調整

使用者選了 C# WinForms + 計分板 + 圖片動畫。

教學重點：開新專案前，先問清楚再寫比寫完才發現方向錯重來划算。多選題比開放題更省雙方時間。

Step 2 — 確認環境（執行前先檢查工具鏈）

dotnet --list-sdks
# 沒回應 → 改用絕對路徑
"C:\Program Files\dotnet\dotnet.exe" --list-sdks
# Exit 145: No .NET SDKs were found.

只有 Runtime 沒有 SDK。這時 Claude 沒擅自下載 SDK，而是用 AskUserQuestion 問了三個選項：

  • 裝 .NET SDK（推薦，後續可重複利用）
  • 用既有的 Visual Studio
  • 只要程式碼自己處理

使用者選 SDK。Claude 才執行：

winget install --id Microsoft.DotNet.SDK.8 --source winget \
    --accept-source-agreements --accept-package-agreements --silent

教學重點：裝軟體、改系統設定屬於「不可逆／影響範圍大」的動作，必須先告訴使用者再做。winget 是 Windows 11 內建套件管理器，靜默安裝旗標可以跳過 GUI。

Step 3 — 建立專案骨架（用 dotnet 模板）

dotnet new winforms -n RockPaperScissors -o . --force

這個指令會自動產出： - RockPaperScissors.csproj（專案設定） - Program.cs（程式進入點） - Form1.cs（視窗邏輯） - Form1.Designer.cs（UI 佈局）

教學重點：不要從零手寫 .csproj，用 dotnet new 找模板。dotnet new list 可看所有可用模板（console、winforms、wpf、web、classlib 等）。

Step 4 — 寫程式碼（兩個檔案分工）

WinForms 的慣例是邏輯與佈局分檔：

檔案 內容
Form1.Designer.cs 純佈局：Label / Button 的位置、大小、字型
Form1.cs 純邏輯：按鈕事件、亂數、勝負判斷、計分

兩個檔案合起來是同一個 partial class Form1。這是 C# 的關鍵語法：partial class 允許把同一個類別拆到多檔。

視覺資源策略：本案例沒有用任何 PNG/ICO 圖檔，而是用 Segoe UI Emoji 字型直接顯示 ✊✋✌——好處：

  • 不需要管圖檔路徑、不需要 embed resource
  • 跨機器執行不會缺檔
  • 程式碼純文字，容易理解
  • 缺點：emoji 風格受限於系統字型；要求高保真才需換 PictureBox + 圖檔

動畫做法：用 System.Windows.Forms.Timer 每 80ms 觸發一次，跑 12 次（總共 ~1 秒）讓電腦端 emoji 隨機跳，最後翻牌定案——這比 async + Task.Delay 簡單，也避免阻塞 UI thread。

Step 5 — 編譯驗證（一定要真的 build 過）

dotnet build -c Release
# 建置成功。0 個警告，0 個錯誤。
# 經過時間 00:00:07.89

產出 bin\Release\net8.0-windows\RockPaperScissors.exe，雙擊即可執行。

教學重點：寫完不算完，編譯通過才算完。Claude 不會把「我覺得這樣應該會跑」當成完成——一定要看到 build success。

從這個案例學到的 5 個通用原則

  1. 動工前先問技術棧：用多選題快速釐清，比寫一半才改省力
  2. 環境檢查放在最前面：缺工具就停下來問，不要硬幹
  3. 不可逆動作要先告知：裝套件、改設定、刪檔都屬於這類
  4. 善用官方模板：dotnet new、npm create、cargo new 都是好朋友
  5. 以 build 通過為完成條件：能跑的 .exe / .app 才算交付

  • 主程式邏輯：Form1.cs
  • UI 佈局：Form1.Designer.cs
  • 編譯輸出：bin/Release/net8.0-windows/RockPaperScissors.exe
