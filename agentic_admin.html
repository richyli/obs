S1Agentic AI 是什麼，跟你現在用的 ChatGPT 差在哪

一句話：Agentic AI = 會主動拿工具、改檔案、串外部服務的 AI——不只是回你一段文字，是在你的電腦上替你做事。

對話式 AI（ChatGPT 網頁版）Agentic AI（Claude Code）
它做什麼回你一段文字讀檔、改檔、跑指令、串政府資料庫
你做什麼複製、貼上、再複製看它做、必要時喊停
一個指令換來一段答案一連串動作 + 一份成品

用「員工」理解——這是全場最重要的一個比喻：

  • 對話式 AI（ChatGPT 網頁版）＝派遣公司每天送新的工讀生來。每次任務來的工讀生都不同，能力不差，但對你一無所知——不認得你單位、不記得你昨天交代過什麼。重點全在每一次都要把任務交代得夠準確。
  • Agentic AI＝養在你身邊的小助理。永遠是同一個人，跟著你久了會認得你的檔案、記得你的慣用語、知道哪些簽呈要會辦人事。重點不在每次交代，而在不斷培養、訓練他。

今天要做的，就是把第二種助理從零帶起來、並且教會他。

S2基本知識：你會一直聽到的幾個詞

下面幾個詞今天會一直出現，先花三分鐘認識，等一下看 demo 就不會卡。不用背，知道大概是什麼就好。

① 它一次回應在做什麼（tool use loop）
你打一句 → 模型決定要不要先用工具（讀檔／搜尋／查行事曆）→ 工具回結果 → 可能再用一次（迴圈）→ 給你最終回應。這個「一邊做一邊決定下一步」的迴圈，就是它跟聊天機器人最大的差別。
② harness（韁繩／載具）
模型本身只是「吃字、吐字」的引擎；它能讀你的檔、跑指令、記住你的偏好，靠的是外面包的一層工程，叫 harness。Claude Code、Cursor、Windsurf 都是 harness——今天用 Claude Code。
③ token（模型算錢、算長度的單位）
模型把文字切成一小塊一小塊，每塊叫一個 token（介於字和詞之間），中文大約 1 字＝1–2 token。為什麼要知道：AI 按 token 計費、一次能讀多少也有上限——所以別把整份幾百頁 PDF 全塞給它，只給要用的那幾頁。
④ context（它這次「看得到」的東西）
這次對話裡它看得到的所有文字——你貼的、它讀過的檔、單位守則、記憶。有上限，塞太多會變慢、變貴、變笨。原則：小事給小 context（別叫它讀整個資料夾），大事拆給分身去做。
⑤ 專案 / 對話 / context 三層
層是什麼何時結束
專案一個資料夾 + 它的設定（含單位守則、記憶）你刪掉資料夾
對話你跟它的一輪互動你關掉視窗或重開
context這一輪它看得到的所有文字塞滿會自動壓縮

同一個專案開 10 次對話，會共用「單位守則」和「記憶」，但每次對話看得到的東西是獨立的。

三個今天會反覆出現的原則： ①看著它跑——它會改你的檔，跑錯後果比聊天大，要看著、要會喊停； ②用 skill 把「你會的事」封裝——教一次，之後一個指令叫出來； ③資料留在你電腦上——產出在你本機資料夾，不是鎖在別人的雲端。
想深入再看：幾個技術名詞（選讀，不看也不影響）
  • Glob：檔案搜尋，用萬用字元（**/*.pdf ＝所有 PDF）。你說「掃我所有回覆檔」，它第一步就是 Glob 把清單抓出來。
  • Bash／PowerShell：命令列環境（黑底白字那個視窗）。Claude 要透過它去跑指令；Windows 預設用 PowerShell、Mac 用 zsh／Bash，它自動偵測，你不用設定。
  • Python：程式語言，AI／自動化最主流。你不用學寫——叫 Claude 幫你寫，它會加註解、會自己 debug。精確計算、批次處理上萬個檔這種「機械活」交給 Python 比較可靠也省錢。
  • 三個旋鈕 Model／Effort／Permission：Model＝引擎大小（Opus 最強最貴、Sonnet 平衡、Haiku 快又便宜，從便宜的試起）；Effort＝思考深度（low／medium／high）；Permission＝動手權限（預設每個寫入都問你，新手一週內所有寫入都看一眼再放行）。
  • 對話太長怎麼辦：快滿時叫它 /compact 自己摘要，或叫它寫一份「交接指南」存檔，新對話讀回去接續。

S3安裝與串接：VS Code + Claude Code

行政同仁多半沒裝過，卡住是正常的。

① 裝 VS Code（你的工作台）

  • 到 code.visualstudio.com 下載 Windows 版
  • 安裝時勾 Add to PATH，其餘保持預設

② 裝 Claude Code CLI（在裡面幫你動手的 agent）

開 PowerShell，貼上官方推薦指令（不需要先裝 Node.js）：

PowerShell
irm https://claude.ai/install.ps1 | iex
  • 被擋「無法載入指令碼」→ 先跑 Set-ExecutionPolicy RemoteSigned -Scope CurrentUser 再重試
  • 公司／學校網路擋下載 → 改用 winget install Anthropic.ClaudeCode

③ 串接 VS Code 與 Claude Code（重點）

兩條路做一條就好：

  • 路線 A（推薦新手）：VS Code 按 Ctrl+Shift+X → 搜「Claude Code」→ Install（擴充套件 anthropic.claude-code）
  • 路線 B：VS Code 開整合終端機 Ctrl+` → 打 claude，它會自動偵測在 VS Code 裡並連上 IDE（外部終端機可打 /ide 手動連）

第一次跑 claude 會跳瀏覽器登入。串接後你會多：編輯器裡並排看 diff、點核准才生效（法規比對會用爆這個）、選取的文字自動變 context、@檔名 帶入檔案。

卡點速查：command not found→重開終端機或重跑安裝；擴充套件裝了沒出現→Ctrl+Shift+P→「Developer: Reload Window」。裝不起來別卡全場，先看 demo。

S4為什麼它能變成「懂你單位」的助理：三層記憶

層是什麼行政場景舉例
CLAUDE.md放專案資料夾的「單位守則」，每次自動讀「公文用行政院格式」「數字用阿拉伯數字」「不可動已發文資料夾」
memory/綁「你這個人」的偏好，跨專案「處長不喜歡『爰此』開頭」「新聞稿結尾不要口號」
skills/把常做的動作封裝成一個指令/院務會議通知、/新聞稿、/法規比對

讓它記住的方法：糾正它之後加一句「把這個規則記下來，下次自動套用」，它就寫進去。這句是全場最重要的技巧——光糾正不說「記下來」，下次它還會犯。

S510 個行政 demo 場景

每個都是老師平常在跑的工作流，換成行政情境。標 🌐 網頁版可做 的下面附可直接複製的 Prompt；標 💻 需 Claude Code 的看老師 demo。每個 demo 的操作時間標在標題右側（⏱），10 個合計約 39 分鐘。

三段式心法（所有 Prompt 的骨架）：背景（你是誰、給誰、什麼事）＋任務（要達成什麼、哪些要件）＋格式（長怎樣、多長）。每留一處空白，AI 就替你自作主張一處。網頁版每個新任務都開一個新對話，要附檔就點輸入框的迴紋針 📎。

Skill demo 標記：🔧 建立 skill = 老師現場把一個重複工作做成一個新指令（教「怎麼把 prompt 變成一鍵 skill」）；⚙️ skill 應用 = 老師跑一個平常已在用的 skill（看成熟 skill 的樣子）。沒有這兩個標記的，就是一次性的 prompt／動作。
💡 同一個情境，prompt 可以怎麼變？三段式是骨架，你可以沿四個方向調—— 詳細度（趕時間少給幾點、重要公文把每個要件寫死）、 對象與語氣（對上級莊重、對同仁平實；保守版或積極版）、 產出形態（要一版成品／要「給我兩版讓我選」／要「你先問我幾個問題再寫」）、 一次到位 vs 分步（直接要成品，或先「列大綱給我確認」再展開）。 下面每個場景，除了主 Prompt，再給你幾個變化版，體會同一件事怎麼換著問。

Demo 1 ｜公文／簽呈起草 🌐 🔧 建立 skill ⏱ demo 4 min

把口頭交辦變成一份格式對的簽呈或函。

Prompt — 把〔〕換成你的資訊
你是我的公文擬稿助理。以下用三段交辦，請據此擬一份公文。

【背景】
- 發文機關：〔○○大學○○處〕
- 受文者：〔總務處〕
- 事由：〔借用會議室並確認投影設備〕
- 補充資訊：〔下週三 14:00–16:00、約 15 人、需投影機與麥克風〕

【任務】
擬一份「函」，要件包含：主旨、說明（分點）、辦法/請求事項。
用語符合台灣公文格式與慣例，正式但不冗贅。

【格式】
- 主旨一句講完，句尾用制式結尾（如「請 查照。」）
- 說明分點列（一、二、三…）
- 全文控制在一頁
- 文號與日期先留〔〕給我填，不要自己編
追問句：「說明第二點太文言，改白話一點。」／「改成『簽』的格式給處長核示。」
文號、日期、法源依據，AI 不要它編——留空自己填、自己核。
🔧 Skill demo（建立）：demo 完 web 版 prompt 後，示範在 Claude Code 把這三段存成 /公文簽呈 skill——下次只喊一聲＋給事由就跑，不用每次重貼。這是把「一次性 prompt」變「一鍵 skill」的第一個示範。
❓ 怎麼把「skill 的觀念」寫進 prompt？把 prompt 拆成兩塊——每次都一樣的規則（你單位的公文慣例）和 這次才變的內容（事由、對象）。不變的那塊就是 skill 的雛形，變的那塊是你每次只要填的空格。下面這版把單位公文規矩寫進 prompt，最後一句還叫它「記住」——等於一邊用、一邊訓練你那位「養在身邊的小助理」。
Skill 版 Prompt — 規則寫進去、只留空格給變數
你是我的公文擬稿助理。【單位慣例】之後每次擬公文都要遵守；【本次任務】才是每次會變的部分。

【單位慣例（固定，之後都照這個）】
- 公文結構：主旨 ＋ 說明（分點）＋ 辦法/請求事項
- 不用「爰此、按」開頭；數字用阿拉伯數字
- 主旨句尾用制式結尾（如「請 查照。」）
- 全文一頁；文號、日期一律留〔〕給我填，不得自行編造
- 語氣正式但白話，不堆砌成語

【本次任務（每次會變）】
- 受文者：〔總務處〕
- 事由：〔借用會議室並確認投影設備〕
- 補充：〔下週三 14:00–16:00、約 15 人、需投影機與麥克風〕

擬好後，請把上面的【單位慣例】記住，之後我說「擬公文」就自動套用。
看懂了嗎：上半段【單位慣例】＝不變、可重複 → 存起來就是 /公文簽呈 skill 的內容；下半段【本次任務】＝每次填的空格；最後一句「記住」＝訓練你的助理（memory）。網頁版可以把【單位慣例】當固定開頭每次貼；Claude Code 才能真的「記住」，之後連貼都不用。
💡 同一情境的變化（換個想法）
  • 想更快：「只要主旨＋說明兩點，其餘免。」
  • 更慎重：「這是要陳給校長的簽，語氣再莊重些，說明補一欄法規依據（依據我後補）。」
  • 要選擇：「給我『保守版』和『積極爭取版』兩版，我挑一版再改。」
  • 讓它先問我：「動筆前先問我三個你需要、但我沒給的資訊，再擬。」

Demo 2 ｜法規逐條比對 💻 🌐 網頁備援 ⏱ demo 5 min

兩版辦法（現行 vs 修正草案）→ 逐條對照表。Claude Code 能並排顯示 diff最好用；網頁版少了並排畫面但能生對照表。

Prompt — 網頁版備援
以下是〔○○辦法〕的「現行版」與「修正草案」，請逐條比對。

【現行版】
〔貼上全文，或上傳檔案〕

【修正草案】
〔貼上全文，或上傳檔案〕

【任務】做一張逐條對照表，欄位：
條號 / 現行條文 / 修正條文 / 變動類型（新增·刪除·修正） / 一句修正重點。
條號有跳動、合併或新增的也要標出來。

【格式】表格。未變動的條標「未修正」即可。
只根據我貼的內容比對，不要推測未提供的條文。
網頁版沒有並排 diff，長辦法容易漏；涉及權利義務的關鍵條號，產出後一定自己再對一次。要並排 diff 就用 Claude Code。
💡 同一情境的變化
  • 只要重點：「只列有變動的條，未變動的別列。」
  • 要影響分析：「多一欄『這條改了對承辦作業的影響』。」
  • 要公文格式：「用公文『修正對照表』三欄：修正規定／現行規定／說明。」

Demo 3 ｜法規適用查詢 + 依據 💻 🌐 ⏱ demo 3 min

貼一份辦法 + 一個實務情境，問它「適用哪條、要不要會辦」。

Prompt
以下是〔○○大學兼任助理請假辦法〕全文，接著我給你一個實務情境。

【辦法全文】
〔貼上全文，或上傳檔案〕

【我的問題】
情境：〔兼任研究助理想請 3 天事假，主管問要不要會辦人事室〕
請告訴我：
1. 這情境適用哪一條（引出條號與原文句子）
2. 你的判斷（要/不要會辦，理由）
3. 哪裡有模糊或例外、需要我回查或問人事室

務必只根據我貼的辦法回答；辦法沒寫到的就說「辦法未規定」，不要自己補。
大字警告：AI 會把不存在的條號講得很篤定（幻覺）。它的答案只能當「該看哪幾條」的指路，最終依據一律回法規原文，不可直接引 AI 的話當公文依據。
💡 同一情境的變化
  • 更保守：「你不確定的地方全部標出來，寧可說『需人事室認定』也不要猜。」
  • 多情境一次問：「同時判斷 A 事假、B 病假、C 公假，各適用哪條。」
  • 要流程：「除了適用條文，幫我列這個請假案的會辦流程（誰→誰）。」

Demo 4 ｜新聞稿一稿多版 🌐 🔧 建立 skill ⏱ demo 4 min

一份活動資訊 → 新聞稿／官網／FB／LINE 四版。

Prompt
你是我的行政公關助理。以下是一場活動的資訊，請一次產出四個平台版本。

【活動資訊】
- 名稱：〔○○系「AI 與新聞」專題演講〕
- 講者：〔○○○ 教授〕
- 時間地點：〔7/20（六）14:00，○○樓 201 教室〕
- 重點：〔開放校內外報名、免費、附茶點〕
- 主辦：〔○○系〕

【任務】產出四版，各自符合平台特性：
1. 新聞稿（正式、倒金字塔、含一句系主任 quote 用〔〕佔位）
2. 官網公告（條列資訊、報名連結〔〕佔位）
3. Facebook 貼文（親切、3–5 行、1–2 個 emoji、結尾行動呼籲）
4. LINE 群組通知（最短、只留重點時間地點＋報名一句話）

【格式】四版各自加清楚標題，方便我分別複製貼出。
追問句：「FB 版再口語一點，開頭用問句抓人。」／「新聞稿加一段講者背景。」
quote、報名連結、確切人數，AI 會留佔位或自己編——換成真的再發。
🔧 Skill demo（建立）：把「一稿四版」的 prompt 存成 /新聞稿 skill，之後每場活動一句話就出四版。對照我平常在跑的 /news-sec——同一個「一份素材→多平台版本」的道理。
💡 同一情境的變化
  • 要兩種語氣：「FB 版給我『正式』和『活潑』兩種，我挑。」
  • 要超短版：「再加一個 50 字的簡訊／跑馬燈版。」
  • 要英文：「加一版英文新聞稿，給國際處用。」
  • 要標題選項：「官網標題給我三個候選，含關鍵字。」

Demo 5 ｜會議紀錄整理 🌐 ⏱ demo 3 min

逐字稿或便條 → 有決議、有待辦的正式紀錄。

Prompt
以下是〔○○會議〕的逐字稿／我的手寫便條，請整理成正式會議紀錄。

【原始內容】
〔貼上逐字稿或便條，或上傳檔案〕

【任務】整理成三塊：
1. 決議事項（每條一句、可執行）
2. 待辦事項（表格：事項 / 負責人 / 期限）— 沒講到的標「待確認」
3. 討論摘要（每個議題 2–3 句）

【格式】用標題分三塊，待辦用表格。
不要加原文沒有的決議；沒共識的標「未決」，不要寫成決議。
追問句：「第 2 案沒有結論，別寫成決議，改列未決。」／「待辦按期限排序。」
AI 常把「討論到的」誤當「決議」——核對哪些是真的拍板。
💡 同一情境的變化
  • 要簡版：「只要決議＋待辦，討論摘要免。」
  • 要正式格式：「用學校會議紀錄格式，逐案排：案由／說明／決議。」
  • 要抓爭點：「另外列出『有不同意見、需再討論』的點。」

Demo 6 ｜一疊 PDF／回覆彙整成總表 💻 ⚙️ skill 應用 ⏱ demo 4 min

各系所回覆的一疊 PDF → 一張總表（系所／重點／是否逾期／缺漏）。老師 demo：它用 Glob 找檔、逐一 Read、產出總表。批次讀十幾個檔是它的日常。⚠️ 掃描檔（無文字層）要另外處理。

⚙️ Skill demo（應用）：這就是我每天在跑的 /read-citavi（批次讀論文 PDF 寫成筆記）——同一型「批次讀 PDF → 彙整」的成熟 skill，套在你們的系所回覆 PDF 上。這裡看的是「一個平常已在用的 skill 跑起來」的樣子。

Demo 7 ｜查政府資料：採購／廠商／法案 💻 ⏱ demo 4 min

串了台灣專屬的 Twinkle MCP 後，直接用講的：「查某機關今年決標公告前 20 件」「用統編查廠商登記與董監事」「查立法院某法案進度」。政府採購、廠商徵信、法案追蹤，大學行政天天碰。

Demo 8 ｜公文／新聞稿校對 + 查證清單 🌐 ⏱ demo 3 min

文件發出前，抓錯字、抓公文用語、把每個數字日期列成查證清單。

Prompt
以下是一份即將發出的〔公文／新聞稿〕，發出前幫我做兩件事。

【文件】
〔貼上全文，或上傳檔案〕

【任務】
A. 校對：列出（1）錯字/漏字（2）不通順或不符公文用語處（3）格式問題，各給修正建議。
B. 查證清單：把文中每個可查證的事實（數字、日期、金額、法條、人名職稱、地點）逐條列出，標出哪些沒附來源、需要我再確認。

【格式】A、B 兩塊分開；B 用表格：事實 / 類型 / 是否已佐證。
只指出問題與建議，不要擅自改動原意。
追問句：「只列你有把握的錯字，不確定的別硬挑。」／「B 表格『需確認』的排最前面。」
AI 校對會漏也會誤報，當「第一道篩子」。它最有用的是查證清單——照著回去核每個數字、日期、法條。
💡 同一情境的變化
  • 只要挑錯：「先別給查證清單，只把錯字和不通順處挑出來。」
  • 要嚴格：「用最嚴格標準，連可能有爭議的用詞都標。」
  • 順查法條：「檢查文中引用的法條條號是否存在，你不確定的註明要我核。」

Demo 9 ｜行事曆祕書 💻 ⏱ demo 3 min

「看我下週哪天最空、幫某會找一小時空檔並建立。」它呼叫 Google Calendar、回一張表 + 建議時段，你說「禮拜三下午建一小時 follow-up」，跳確認、按 Enter 就建好。你描述意圖，它選工具、執行、確認——這就是 agentic 的感覺。

Demo 10 ｜把重複工作固化成 skill + 記住單位慣例 💻 🔧 建立 skill ⚙️ skill 應用 ⏱ demo 6 min（壓軸）

每月的「院務會議通知」格式每次一樣、只換日期議程。值得做成 skill 的＝頻率高、步驟固定、輸入輸出講得清楚。

🔧 建立 → ⚙️ 應用（完整生命週期，一次演完）： ① 建立：現場把它做成 /會議通知 skill（背景/任務/格式寫死、存起來）。 ② 應用：馬上喊一次 /會議通知，給日期議程就跑出通知。 ③ 訓練：糾正一句公文用語後說「把這規則記下來」，寫進 memory，下次自動套用。 這一段把前面所有 demo 收束成一句話——重複的事，做成 skill、用 skill、再教 skill。

S6怎麼把 demo 變成你每天在用的

demo 看起來很神，真正的價值在它會跟著你長大，靠一個循環：

  1. 你叫它做（/會議通知）
  2. 它做出 90% 對的東西
  3. 你看出那 10% 不對 → 講「應該是 X 不是 Y」
  4. 它修正當下結果
  5. ★ 你接著說「把這個規則記下來，下次自動套用」
  6. 它寫進 SKILL.md / memory
  7. 下次跑 → 自動 100% 對

第 5 步最容易漏。規則記得好一點的寫法，是連「為什麼」一起記（例：「不用『爰此』開頭 — Why：處長改過兩次 — How：改用『有關…一案』」），遇到邊角情況它才知道該不該套用。這就是「訓練 AI」的真相——沒有 GPU、沒有資料集，就是「做一次 + 糾正 + 記下來」重複幾十次。

Take-away：回去挑一件每週重複的事（擬同類公文、發同類通知、整理同類回覆），先做給自己用，好用了再想能不能分享給同事。使用 AI 的目的不是效率本身，是把重複的事交出去之後，你想把時間花在什麼更值得的事情上。
