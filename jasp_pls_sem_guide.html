2. Model 面板

JASP PLS-SEM 的 Model 面板可能有以下子區（待呂欣截圖確認）：

2.1 Variables / Indicators 指派區（推測）

很可能 Model 面板的最上方有一個變數列表 + 指派框：

  • 左側：所有可用變項清單（CSV 中所有欄位）
  • 右側：必須把要分析的變項拖入指派框（例如 Variables 或 Indicators）
  • 動作：把 12 題構念題（BI1–JPB3）+ 9 題互動產品（ASExJPB_11 至 _33，若做調節）全部拖入

→ 變項沒拖入 = JASP 不知道分析誰 = bootstrap 跑不了

2.2 Latent Variables 區（推測）

可能類似 JASP CB-SEM 的 Latent Factors 區：

  • 點 ➕ 新增 Latent Variable（命名 JPB、APT、ASE、BI）
  • 對每個 Latent Variable，把對應指標拖入

這個 UI 操作可能與 syntax 框並存： - 拖入 UI = 自動產生 =~ 測量模型語法 - 結構路徑 ~、標籤 *、derived := 仍在 syntax 框寫

2.3 Model syntax 框

語法輸入區。結構路徑、構念相關、derived parameters 寫在此：

# 結構路徑（lavaan 語法）
APT ~ a*JPB + ASE
BI  ~ c*JPB + b*APT

# 構念相關
JPB ~ ASE
ASE ~ BI

# Derived
indirect := a*b
total    := c + indirect

注意：若 Latent Variables 已在 UI 區指派，不需要重複寫 =~ 行（會衝突）。

若 UI 無法處理結構（例如 PLS-SEM 預設只做 measurement），則所有 =~、~、:= 都寫在 syntax。

此點需呂欣實測截圖確認。

2.4 Grouping Variable

  • 預設：<no choice>
  • 用途：多群組分析（PLS_MGA）時把分組變項拖入此框
  • 呂欣的應用：Phase 9 的 PLS-MGA 比較資深 vs 資淺記者時，把 seniority_group 拖入

2.5 解決 Bootstrap 不跑的步驟

依優先順序試：

  1. 確認所有 Likert 變項都拖入 Model 面板的 Variables / Indicators 框（最可能原因）
  2. 確認所有變項類型為 Scale（橘色斜線）
  3. 確認 Estimation → Error calculation method 勾 Bootstrap
  4. 確認 Bootstrap samples 不為 0
  5. 若 syntax 寫了 =~ 又同時 UI 拖入，移除其中一個避免衝突
  6. 若仍跑不出來，把 Bootstrap samples 暫時調為 100 測試（成功後再調 5000）

3. Estimation 面板

3.1 ☑ Consistent partial least squares（PLSc）

  • 截圖預設：✅ 已勾選（呂欣本研究 2026-05-09 改取消勾選，原因見下文「失控警告」）
它在解決什麼問題？

傳統 PLS（Mode A）的偏誤：把每個構念當作指標的線性組合（composite）估計，等於假設指標沒有測量誤差。但 reflective 模型理論上認為「構念導致指標」（指標有測量誤差），所以傳統 PLS 系統性產生：

  • 外部負荷量 $\lambda$ 被低估（measurement attenuation）
  • 結構路徑 $\beta$ 被高估（因為構念變異被低估，路徑被相對放大）
  • 與 CB_SEM（factor-based）的估計不一致

這個偏誤在傳統 PLS 文獻中稱為 PLS bias（Dijkstra, 2014）。

PLSc 怎麼修正？

Dijkstra_Henseler 2015 提出的 Consistent PLS 對每個 reflective 構念的負荷量做一次 disattenuation：

$$\lambda_{\text{PLSc}} = \lambda_{\text{PLS}} \times \sqrt{\frac{\rho_A}{\rho_{\text{PLS}}}}$$

其中 $\rho_A$ 即 rho_A（Dijkstra-Henseler's $\rho$，JASP 表中的「Dijkstra-Henseler's ρ」），$\rho_{\text{PLS}}$ 為傳統 PLS 估計的合成信度。

結果： - 負荷量被「拉高」回 reflective 模型應有的水準 - 構念分數變異隨之調整 - 結構路徑被「壓低」回理論值 - 估計值近似 CB-SEM；與 lavaan 對照時兩者通常差 < .03

直觀理解：把傳統 PLS 的每個 reflective 構念都「修一次測量誤差」，使結果像 factor-based 模型一樣可信。

何時建議勾選？
情境 建議
全部 reflective 構念 + 樣本充足（N > 200）+ 信度全部達標（α、$\rho_A$ ≥ .80） ✅ 勾，標準作法
全部 reflective 構念 + 樣本中等（100-200）+ 信度達標 ✅ 勾，但建議同時跑關閉版作 robustness
含 formative 構念 ❌ 不勾（PLSc 數學上不適用 formative）
信度邊緣（$\rho_c < .70$ 或某構念 $\rho_A$ 與 $\rho_c$ 差距 > .10） ⚠️ 注意失控風險，先試關閉再決定
小樣本 N < 100 + 邊緣信度 ❌ 高失控風險（呂欣本資料）
⚠️ PLSc 失控警告（呂欣 2026-05-09 親身踩到）

當下列條件多項同時成立時，PLSc 的 disattenuation 會失控、放大估計不穩定性：

  1. 某構念 $\rho_c < .70$
  2. 該構念的 $\rho_A$ 顯著高於 $\rho_c$ 與 $\alpha$（差距 > .10）
  3. 樣本量小（N < 150）
  4. 構念之間有複雜符號型態（部分指標跨構念呈正/負混合相關）

失控徵狀： - 結構路徑 $|\beta| > 1$（標準化下數學上不可能） - bootstrap SE > 5（健康時 < 0.3） - 部分構念的指標 loadings 全部不顯著 - SRMR / CFI / GoF 等擬合指標大幅惡化

呂欣本研究 2026-05-09 實跑結果： - ASE 構念 $\rho_c = .672$，$\rho_A = .855$（差距 .183） - 觸發 PLSc 失控：BI ← JPB 路徑 $\beta = 1.263$、SE = 21.75 - ASE loadings 全部 $p > .10$ - SRMR = .152、CFI = .766

因此呂欣本研究決定取消勾選 PLSc，改用標準 PLS Mode A，理論討論時引述：

「考量本研究樣本量（$n = 96$）偏小、ASE 構念 $\rho_c$ 處於 .70 邊緣，採用 Dijkstra_Henseler 之 PLSc 修正會觸發 disattenuation 失控（路徑係數逾越標準化邊界），故主分析採傳統 PLS Mode A，並於 robustness check 中報告 PLSc 對照（Sarstedt_2020）。」

取消勾選後的代價（誠實揭露）
  • 結構路徑 $\beta$ 可能略高估（PLS bias 問題本身仍存在）
  • 與 CB-SEM 對照可能略有差距（< .05）
  • 論文 Methods 章節必須明確說明使用「傳統 PLS Mode A」而非 PLSc，並引上述失控原因
  • 補做 CB-SEM（lavaan）作為主要 robustness check 平衡 PLS bias 疑慮

3.2 Inner weighting scheme

下拉選單，預設 Path。三個選項：

選項 說明 何時用
Path（預設） 路徑加權法；穩定且推薦 一般情境（Hair_2022_PLS 推薦）
Centroid 重心加權；最早期 PLS 預設 純探索性、無方向假設時
Factorial 因子加權；對共變數較敏感 與 CB-SEM 比較時
  • 呂欣建議：保持 Path（業界標準）

3.3 ☐ Ignore structural model（截圖中灰色）

  • 截圖中此選項呈灰色不可勾選，可能因為 PLSc 已啟用導致鎖定
  • 作用：若勾選會跳過結構模型估計，只跑外模型
  • 呂欣建議：不需動，保持原狀

3.4 Convergence criterion

下拉選單，預設 Absolute difference。常見選項： - Absolute difference（預設）：權重變化小於 tolerance 即停 - Squared difference：權重平方差小於 tolerance

  • 呂欣建議：保持預設

3.5 Tolerance

  • 預設：1e-05（即 $10^{-5}$）
  • 作用：收斂閾值；越小越嚴格
  • 呂欣建議：保持預設（Hair_2022_PLS 標準）

3.6 Error calculation method（重要）

兩個選項（互斥）：

○ None
  • 不算 SE / CI；只跑點估計
  • 呂欣不要選（無法做假設檢驗）
● Bootstrap（呂欣必選）
  • Samples：截圖預設 200 ⚠️
  • 呂欣本研究改為 1000（Hair_2022_PLS 列為最低可接受標準）
  • 200 太少，bootstrap CI 不穩定
  • 本資料無法跑 5000：呂欣實測 5000 即使設 Ignore/Drop 仍失敗，可能是 JPB1 天花板效應導致退化 sample 累積過多（5000 次中近半失敗 → 觸發 JASP 內部錯誤）；1000 次成功
  • 期刊主流 5000，但 1000 完全可接受，論文中註明即可
  • Confidence intervals：預設 95 %
  • 呂欣保持 95%
  • Handling of inadmissibles（怎麼處理 bootstrap 中估計失敗的 sample）：
  • ○ Replace（截圖預設）：失敗就重抽一次
  • ● Ignore（呂欣論文必選）：失敗的 sample 直接跳過
  • ○ Drop：丟掉整個 boot set
  • 本研究強制改 Ignore 的原因：JPB1 有強烈天花板效應（$M = 4.93$, $SD = 0.30$），bootstrap 在某些子樣本中可能抽到 JPB1 變異為 0，導致估計失敗。Replace 會反覆重抽同類退化樣本，最終卡死跳「NAs are not allowed」錯誤。Ignore 跳過這些失敗 sample，bootstrap 能順利跑完，CI 略不穩但實務上完全可用

3.7 Repeatability（重要）

  • ☐ Set seed：截圖預設未勾選
  • 預設值：1

呂欣必須勾選並改 seed = 42（或任意固定數）： - 不勾的話每次跑結果略有差異（bootstrap 隨機） - 設 seed 確保論文結果可重現 - 用 seed = 42（與 Python plspm 預跑相同，方便對照）

JASP 實際欄位（與論文常用名對照）：

Latent 構念名稱 —

Jöreskog's ρ CR_Composite_Reliability $\rho_c$（組合信度／合成信度） .70–.95
Dijkstra-Henseler's ρ rho_A（PLSc 一致信度，Dijkstra_Henseler 推薦） ≥ .70

→ 論文寫作關鍵對應：JASP 標 Jöreskog's ρ 即 Hair_2022_PLS 所稱的 $\rho_c$ 或 CR；JASP 標 Dijkstra-Henseler's ρ 即一般文獻的 $\rho_A$。論文敘述時建議寫：「組合信度（$\rho_c$，JASP 顯示為 Jöreskog's $\rho$）介於 …」首次出現時做一次標註，之後直接用 $\rho_c$。

→ AVE 不在此表：JASP 0.19.3 PLS-SEM 模組未直接輸出 AVE，需手動計算 $\text{AVE} = \frac{1}{k} \sum \lambda_i^2$（用下節 Loadings 表平方後平均）。

9. 常見錯誤排除

Q1：跑出來只有點估計沒有 CI / t / p

A：Estimation → Error calculation method 確認勾 Bootstrap（不是 None）

Q1.5（呂欣 2026-05-09 確認解法）：跑 bootstrap 跳「Error in model 'Model' - Estimation failed Message: NAs are not allowed in subscripted assignments」

A：Estimation → Bootstrap → Handling of inadmissibles 從預設 Replace 改 Ignore，問題即解決。

原因：本研究 JPB1 指標有強烈天花板效應（$M = 4.93$, $SD = 0.30$），96 位受訪者中絕大多數答 5。Bootstrap 抽樣時某些子樣本可能剛好抽到 JPB1 全為 5，導致該指標變異為 0，進而觸發以下兩種數值問題： 1. PLSc 修正分母為零（rho_A 計算失敗） 2. 構念負荷量無法估計（變異為 0 的指標無法計算 standardised loading）

當「Handling of inadmissibles」設為 Replace（預設）時，JASP 會反覆重抽，但同類退化樣本會持續出現，最終估計卡死跳 NA 錯誤。改為 Ignore 後，JASP 跳過失敗 sample，剩下成功的 sample 仍可估計 CI（多數 sample 會成功）。

對 bootstrap 結果的影響：實際有效 boot 次數略小於設定值，CI 略不穩定但實務上可接受。

呂欣 2026-05-09 後續實測：即使設 Ignore/Drop，5000 次 bootstrap 仍失敗，1000 次成功。可能原因：5000 次中累積失敗率過高（推估約 30-50% sample 退化），剩餘成功 sample 數過少觸發 JASP 內部其他錯誤。最終採用 1000 次 bootstrap——這是 Hair_2022_PLS 列為「最低可接受」的標準（5000 為主流但非強制）。

論文限制寫法建議：

由於 JPB1 指標呈強烈天花板效應（$M = 4.93$, $SD = 0.30$），導致 bootstrap 重抽過程中部分子樣本之 JPB1 變異趨近於零、估計失敗。經測試，在 5000 次重抽下失敗 sample 累積過多致無法收斂，故依 Hair et al. (2022) 對 PLS-SEM bootstrap 之最低標準建議，採 1000 次 BCa bootstrap，並於 Handling of inadmissibles 設定 Ignore 以跳過退化 sample。1000 次重抽足以穩健估計路徑係數之 95% 信賴區間（Streukens & Leroi-Werelds, 2016）。

Q2：每次重跑數值都略不同

A：Repeatability → ✅ Set seed（必勾），固定 seed 為任意數（推薦 42）

Q3：bootstrap 跑很慢

A：Samples 預設 200，改為 5000 約 30-90 秒；若超過 5 分鐘，檢查模型是否過於複雜（互動項過多）

Q3.7（2026-05-09 新增）：跳警告 Only a subset of population values given. please specify all population values or none

A：發生於 syntax 使用 lavaan 風格的路徑標籤（如 a1*JPB）時。根因是 seminr 對 * 算子的解讀與 lavaan 不同：

算子 標準 lavaan 解讀 seminr / JASP PLS-SEM 解讀
a1*JPB 把路徑標籤命名為 a1（用於 :=） 把路徑的母體真值（population value）設為 a1
0.5*JPB 把路徑固定在 0.5 同上

當 syntax 內只有部分路徑標 * 而其他構念對自由相關（沒有 *），seminr 認為「你只給了一部分母體值」就跳此警告。

先確認是否致命：看右側結果區是否有 Regression Coefficients 表，以及是否有 indirect 與 total 兩列。

情境 1：結果有跑且 indirect / total 兩列出現 → 警告無害，可直接判讀。

情境 2：結果有跑但沒有 derived parameter 兩列 → := 在 JASP PLS-SEM 不被支援。改用以下無標籤版本：

APT ~ JPB + ASE + ASExJPB
BI  ~ JPB + APT

從 Regression Coefficients 表抄五個 β 對應論文符號（$a_1$ = β(APT←JPB)、$a_3$ = β(APT←ASExJPB)、$b$ = β(BI←APT) 等），於 Excel 用 Sobel_test 公式手算 IMM = $a_3 \times b$ 與其 95% CI（呂欣本研究堅持 JASP-only 工作流；不依賴 R）。詳細步驟見 handout Phase 4/6。

情境 3：結果完全沒跑出來 → 改用無標籤版本（情境 2 的 syntax），重跑。

Phase 4 / 5 / 6 的因應（JASP-only 工作流）： - Phase 4 中介：indirect 與 total 改從 Total Effects 表回推（$\text{indirect} = \text{total} - c'$），CI 用 Sobel 近似 - Phase 5 互動：a3 直接從 Regression Coefficients 看（β(APT←ASExJPB)），無需衍生參數 - Phase 6 IMM 與 conditional indirect：用 Sobel 與 Aroian 公式於 Excel 算，論文中註明 Sobel 之常態假設限制

Q4：跳警告 All construct correlations must be supplied explicitly

A：syntax 是純測量模型（只有 =~、沒有任何 ~ 結構路徑）時出現。解法是加上理論結構路徑（不是補相關）；Loadings / Reliability / HTMT 只取決於外模型，加結構路徑不影響其值。

Q3.5（2026-05-09 新增）：路徑係數超出 [-1,+1]、SE 爆 > 20、ρ_A 異常高於 ρ_c

A：PLSc（Consistent PLS）估計爆炸。標準化路徑係數應在 [-1,+1] 之間；當你看到 β = 1.263、SE = 21.75 這類數字，代表 PLSc 對邊緣信度構念過度 disattenuation，放大了構念相關矩陣的條件數，逆矩陣失控。

徵狀組合（同時出現多項即確認）： - 結構路徑 |β| > 1（標準化下不可能） - SE > 5（PLS bootstrap SE 通常 < 0.3） - ρ_A 顯著高於 ρ_c 與 α（健康時三者接近） - 部分構念的指標 loadings 全部不顯著（即使 raw correlation 顯示構念正常） - 整體擬合（SRMR、CFI、GoF）大幅惡化

解法（依序試）：

  1. 取消 Estimation 面板的 ☑ Consistent partial least squares：改用標準 PLS Mode A。多數 PLS 論文 PLSc on/off 並存報告作 robustness
  2. 若關 PLSc 仍異常：找信度最弱、loadings 最低的構念，考慮刪除最弱指標（保留 ≥ 2 題）
  3. 最終手段：改 CB-SEM（lavaan）為主分析，PLS 作 robustness

呂欣本資料的觸發原因：ASE 構念 ρ_c = .672 略低於 .70 門檻，PLSc 試圖把 loadings disattenuate 到 ρ_A = .855，造成構念相關矩陣 near-singular。

Q4.5（2026-05-09 新增）：跳錯誤 Reordering the structure equations was not successful

A：結構模型有循環（cycle），不是 DAG。後端 seminr 用拓撲排序處理結構方程，模型必須是有向無循環圖。

最常見原因：誤把外生變項之間或從終點反向連回的「相關性」當結構路徑寫，例如： - JPB ~ ASE + APT ~ ASE + APT ~ JPB（看似補相關，實際讓 ASE 同時是 JPB 與 APT 的前因） - ASE ~ BI + APT ~ ASE + BI ~ APT（造成 BI → ASE → APT → BI 循環）

解法：移除非理論預期的 ~ 行；外生變項之間的相關性 PLS 自動處理，不需要也不能用 ~ 補。

規則：每條 ~ 都要對應一個你願意在論文中假設、有理論方向的結構關係。沒有方向的不要寫。

Q5：HTMT 沒看到

A：可能在「Reliability measures」勾選後出現；或在 Output 面板下方有獨立「Discriminant validity」選項；若仍無，用 R seminr 計算（見 handout_pls_sem_final.md 附錄 A）

Q6：路徑係數出現負值，但理論預期正向

A：Sign indeterminacy 問題；改 Estimation 中找 Sign change 選項設為 Construct level changes（若截圖中沒看到，可能在某個展開項中）

Q7：估計不收斂

A： 1. 增加 Tolerance（如改成 1e-04，較寬鬆） 2. 確認資料無極端 outliers 3. 互動項與主效果共線性過高 → 改用 mean-centered indicators
