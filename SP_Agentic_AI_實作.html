SP Agentic AI 實作 — 學生自學包

這份帶你自己走完一堂「把會動手的 AI agent 跑起來、再固化成個人工作流」的實作課。你會真的動手兩次：第一次讓一個 agent 幫你處理一段真實工作，第二次把它包成一個一鍵叫用、還能自己接資料的 skill。全程記住一句話：你負責下指令＋驗收，它負責執行。

讀完你能

# 層級 你會的能力 你就答得出的真實問題
1 理解 區分 agent／chatbot／workflow 為什麼說 Claude Code 不是「比較聰明的聊天框」？
2 應用 用三段式（背景／任務／格式）下指令，讓 agent 處理一段真實工作 為什麼同一個指令，我跑出來爛、別人跑出來好？
3 應用 設計並做出一個自己的 skill，必要時用 MCP 接資料 我每週都在做的哪件事，最值得包成 skill？
4 分析 判斷 skill 為什麼跑歪、agent 哪步該放手哪步該接手 為什麼別人照我的 skill 跑，結果卻不一樣？

開始前準備三件事

  1. 一台電腦。
  2. 一段你自己的真實工作檔：訪談逐字稿／一份報告／一封要回的長信都行——等下你要拿它動手。
  3. 裝好 Claude Code（沒裝也沒關係，Part 1 第一步就帶你裝）。

🤖 先跟 AI 過一招（動手前 10 分鐘）

貼這段給 AI（ChatGPT／Claude／Gemini 皆可）：

「請用生活比喻解釋 AI agent、chatbot、workflow 三者差在哪，各舉一個我工作上會遇到的例子。接著反過來問我：我每週固定重複、步驟又差不多的工作有哪些？幫我列 3 件，並判斷哪一件最適合交給一個會動手的 AI agent 去做。」

拿到答案後追問一次：

「你說最適合的那件，如果我完全不會寫程式，真的做得到嗎？卡點會在哪？」

看它會不會改口或含糊帶過。把它列的那 3 件重複工作記下來——待會 Part 2 你要把其中一件，真的做成一個 skill。這件事就是你今天自學包的素材。

Part 1 — 讓 agent 第一次在你電腦上動起來

① 裝起來，跑第一個指令

先建立正確心智模型：Claude Code 不是聊天機器人，是一個會幫你動手做事的 agent——它會讀你的檔案、寫檔案、跑指令。目標只有一個：讓它在你電腦上動起來，跑完一件你真的在做的工作。

安裝四步，一步一步來：

  1. 確認有 runtime（Node.js 之類）→ 終端機打版本確認指令。看到 command not found 不要慌，這是 99% 新手第一關，代表電腦還不認得這個字。
  2. 安裝 Claude Code CLI。卡點通常是權限（Mac 要不要 sudo、Windows 要不要系統管理員）或公司／學校網路擋下載。
  3. 第一次啟動要登入／授權。金鑰像鑰匙，不要貼到群組裡。
  4. cd 到一個資料夾再啟動。記住：Claude Code 是「在某個資料夾裡工作」的，你站在哪個資料夾，它就只看得到那個資料夾的檔案——這點等下很關鍵。

裝好後，下一個無風險暖身指令，例如請它「用一句話說明這個資料夾裡有什麼」。你會注意到三件事：

  • 它會先講它打算做什麼，再動手——這就是你「驗收」的第一個介面。
  • 它會問你要不要授權讀／寫檔案——這個確認鍵就是人類的煞車，不要無腦一直按 yes。
  • 同一個指令、不同人結果不一樣——結果好不好，取決於你怎麼問。

② agent 到底跟 chatbot、workflow 差在哪

會動你的檔案？ 會臨場判斷？ 例子
chatbot ✗ ✗（一問一答） 一般對話框
workflow ✓（固定步驟） ✗（照表操課） 自動化腳本
agent ✓ ✓（規劃＋調整） Claude Code

它強在「會做事＋會臨場判斷」，但也因為這樣，你更需要會驗收。搭配三個比喻先聽過（Part 2 會真的用到）：

  • skill＝可重複的食譜：把你常重複下的一串指令，固化成一鍵叫用的流程。
  • MCP＝接資料源的轉接頭：讓它伸手去資料夾以外的地方（試算表、行事曆、開放資料）拿料。
  • hook＝自動觸發的開關：當 X 發生就自動做 Y，不用你喊。

③ 動手：用你的真實工作跑一次

拿出你帶來的真實檔案，請 Claude Code 對它做一件有用的事：

  1. 放料：把檔案丟進你 cd 的那個資料夾，確認站的資料夾裡看得到它。
  2. 下指令（三段式）：
  3. 背景：「這是一份我訪談 OO 的逐字稿。」
  4. 任務：「幫我抓出三個主要論點，每個配一句原文佐證。」
  5. 格式：「用條列，每點不超過兩行。」
  6. 先讀它的計畫再放行——這就是你在驗收。
  7. 放行／煞車：合理就放行；它要動你不想動的檔案就按煞車。
  8. 看結果，立刻標記「對一處／錯一處」，並判斷不夠好的話你會改哪一段（背景、任務、還是格式？多數人第一次都漏給背景或沒講格式）。

造例子（一定要做）：換一個你自己的檔、自己寫一組三段式指令再跑一次。能不能講清楚「背景／任務／格式」，就是你會不會用它的分水嶺。

Part 2 — 把它固化成一鍵叫用、還能接資料的 skill

① 什麼值得做成 skill

先講判準，再動手。三條判準：

  1. 頻率高——你每週、每天都在做（一次性的事不值得固化）。
  2. 步驟固定——流程大致一樣，不是每次都長得不同。
  3. 輸入輸出講得清楚——你能描述「丟什麼進去、要吐什麼出來」。

反例校正：「幫我想一個 idea」不適合——步驟不固定、輸出也說不清。「把這週五篇稿子彙整成一頁主管週報，每篇三行、附連結」就非常適合。

worked example（週報彙整）——把腦袋裡的流程描述成三段式：

段 內容
背景 你是我的編務助理，每週五給你本週稿件清單
任務 ①逐篇一句重點 ②標數據最佳的幾篇 ③彙整一頁、每篇三行附連結 ④給三句選題建議
格式 Markdown、一頁、主管掃一眼就懂

把這三段存成一個 skill（取名 週報彙整），下次喊名字＋丟清單就跑。你發現了嗎——skill 不是新東西，它就是你 Part 1 學的三段式指令，被存起來、給它取個名字。

② 用 MCP 讓料自己流進來

剛剛的 skill 有個天花板：料是「你貼給它的」。如果料根本不在你資料夾裡、在試算表、在政府開放資料庫呢？這就要 MCP。

料從哪來？ 你要做什麼
沒 MCP 只看得到你的資料夾 每次手動把試算表複製貼上
插上 MCP 伸手到試算表／開放資料／行事曆 喊一聲，它自己去把料讀進來

批次產製是這裡的殺手鐧：一份素材要 FB／IG／LINE／電子報四個版本，過去手動改四遍；寫成 skill＋MCP 自動拉料，喊一聲就一次吐四版。這是「人力 × 平台數」的放大。

③ 動手：做你自己的第一個 skill

用你課前跟 AI 挑出的那件每週都做、步驟又固定的事：

  1. 挑事：對照上面三條判準——頻率高嗎？步驟固定嗎？輸入輸出講得清楚嗎？三條都中再往下。
  2. 寫三段式：背景、任務、格式三段各寫死。每留白一處，AI 就替你自作主張一處。
  3. 存成 skill：給它一個一看就懂的名字。
  4. 跑一次：喊名字、丟料、先讀計畫再放行。
  5. 驗收：結果出來立刻標「對一處／待修一處」，並判斷待修的是 prompt（哪段留白了）還是 資料（根本沒接到料）。

造例子（一定要做）：把你做好的 skill，想像交給同事跑。它會不會跑出不一樣的結果？先自己找出「最可能跑歪的那一段」。

🧪 自測三題（先自己答，答案線索在後，別偷看）

  1. （理解） 你朋友說「Claude Code 就是比較會查資料的 ChatGPT」。用一句話反駁他，關鍵字要出現「動檔案」和「臨場判斷」。
  2. （應用） 你下了「幫我整理一下這份報告」，結果一團亂。這句指令三段式裡少了哪幾段？補完它。
  3. （分析） 你的 skill 自己跑很順，但同事照著跑結果完全不同。列出兩種可能病因，並各給一個檢查動作。
答案線索（想過再打開） 1. chatbot 不會動你的檔、也不臨場判斷；agent（Claude Code）會讀寫檔、跑指令、看結果再調整。 2. 少了**背景**（你是誰幫誰、這是什麼文件）和**格式**（輸出長什麼樣、多長）。只有一句模糊「任務」，AI 只能自由發揮。 3. 病因一＝**prompt 留白**（某段沒寫死，AI 各自發揮）→ 檢查三段式哪段偷懶了；病因二＝**沒接到資料源**（其實只是純文字模板，料每次靠手貼，同事貼的料不同）→ 檢查它是不是真的透過 MCP／檔案自己拿到料。

✍️ 自學反思 + 講給一個人聽

寫下一句：「我下週會把哪一件每週都在做的事，包成自己的第一個 skill？它最可能卡在 prompt 還是資料接不上？」

然後找一個人（同學、同事、家人）把今天做的 skill 講給他聽——講到對方也聽懂「為什麼這件事值得固化」，你才算真的會了。把雜務卸給 AI 沒問題，但判斷與選題留給自己，不然你會連它跑歪了都看不出來。

🚫 迷思自測（你覺得對嗎？先判斷再翻答案）

# 說法 你覺得對嗎？
1 「不會寫程式的人用不了 Claude Code。」 ⬜ 對 ⬜ 錯
2 「skill 是一種很進階的新東西。」 ⬜ 對 ⬜ 錯
3 「接了 MCP 之後就全自動，不用我看了。」 ⬜ 對 ⬜ 錯
4 「授權確認一路按 yes 最快。」 ⬜ 對 ⬜ 錯
翻答案 1. **錯**。Anthropic 一位從沒寫過程式的銷售（見 Case - GTM Engineering at Anthropic），把自己的工作流做成工具、每天省 2–3 小時。關鍵是「會下指令、會驗收」，不是會 coding。 2. **錯**。skill 就是你下過、驗收過、確定好用的那串三段式指令被存起來、取個名字。差別只在以前每週重打、現在喊一聲就跑。 3. **錯**。MCP 讓料自己流進來，但產出仍要你驗收；沒接資料源的 skill 再漂亮也只是純文字模板。 4. **錯**。確認鍵＝人類的煞車。它要動你不想動的檔時就是要你按煞車的時刻，無腦放行等於拿掉把關。

🤝 卡住時怎麼問 AI（可直接複製）

  • 裝不起來：「我在 <你的作業系統> 上裝 Claude Code，跑到 <哪一步> 出現 <錯誤訊息>。請一步一步告訴我最可能的原因和修法，先問我兩個釐清問題再給解法。」
  • 指令跑歪：「我下了這個指令：<貼指令>，結果是 <貼結果>，但我要的是 <你要的>。請指出我的三段式（背景／任務／格式）哪一段沒寫清楚，並幫我改寫一版。」
  • 不懂 MCP：「請用『轉接頭』的比喻，舉一個我這行（<你的職務>）真的會用到的例子，說明沒 MCP 跟接了 MCP 差在哪。」

⚠️ AI 最常在這裡胡說：Claude Code 的具體指令語法、MCP 怎麼設定、某個 skill 的檔案位置，AI 很可能講得頭頭是道卻是錯的（這類新工具的操作細節它常編）。凡是「操作步驟」層級的回答，以官方文件與你當場實測為準，別照 AI 的步驟盲抄。

讀完的一句收斂

好結果不是找到更強的模型，是你把指令講清楚、該放手時放手、該接手時接手。三段式每留白一處，AI 就替你自作主張一處；值得做成 skill 的＝頻率高、步驟固定、輸入輸出講得清楚。
